# Как поддерживать документацию

**Тип материала:** учебный регламент. Это предложенный процесс, не описание действующей корпоративной практики.

## Приоритет читателя

1. Пользователь хочет знать, **как начать и что нажать**. Для него предназначен `USER_GUIDE.md`.
2. Разработчик хочет **установить, найти ответственный модуль и внести изменение**. Для него `README.md` и `MAINTAINER_GUIDE.md`.
3. Человек с ошибкой хочет **узнать причину и восстановить работу**. Для него `TROUBLESHOOTING.md`.

## Минимальный процесс изменения инструкции

1. **Повод**: появилась новая команда, баг, изменение интерфейса или обратная связь.
2. **Источник истины**: прочитать реализацию и воспроизвести поведение; если доступа к рабочему боту нет, явно пометить это ограничение.
3. **Черновик**: записать сценарий через действие пользователя и ожидаемый результат, не через внутренние имена классов.
4. **Техническая проверка**: сверить с разработчиком или исходниками команды, аргументы, предупреждения, названия элементов.
5. **Редактура**: убрать лишнее, проверить термины и ссылки, разбить длинные процедуры на шаги.
6. **Проверка**: пройти все шаги на чистом окружении; зафиксировать непроверенные места.
7. **Выпуск**: обновить связанные документы в одном коммите или PR.

## Чек-лист публикации

- [ ] Для кого написано и какую проблему решает?
- [ ] Есть условия до начала работы?
- [ ] У каждого шага есть понятное действие и наблюдаемый результат?
- [ ] Названия кнопок и команд совпадают с текущим интерфейсом?
- [ ] Неподтверждённые свойства не объявлены рабочими?
- [ ] Есть раздел с ошибками и безопасным обращением с токеном?
- [ ] Внутренние ссылки и примеры работают?
- [ ] Инструкцию сможет выполнить человек, не читавший код?

## Что демонстрирует этот набор

**Исходное состояние:** публичный репозиторий без README, пользовательского руководства и диагностики.

**Результат:** отдельные документы для конечного пользователя и разработчика, карта модулей, пошаговый запуск, диагностика и исправление обнаруженной сигнатуры обработчика и предложенный процесс обновления.

Часть документации составлена с помощью ИИ. Перед представлением её как личной работы важно самостоятельно перечитать и выполнить все инструкции.
