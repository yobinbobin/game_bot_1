# Диагностика неполадок

**Аудитория:** тот, кто запускает или сопровождает учебного бота.

Начни с воспроизведения проблемы и просмотра сообщения об ошибке в терминале. Никогда не отправляй токен бота в issue, чат или скриншот.

| Симптом | Вероятная причина | Что проверить |
| --- | --- | --- |
| `ModuleNotFoundError: aiogram` | Не установлены зависимости или выбран не тот Python | Активируй окружение, выполни `python -m pip install -r requirements.txt` |
| `EnvError` или отсутствует `BOT_TOKEN` | Нет файла `.env` или не задана переменная | Создай локальный `.env`; запусти из корня проекта |
| `TokenValidationError` / ошибка авторизации Telegram | Неверный или отозванный токен | Сверь локальную настройку с @BotFather, не публикуй токен |
| Скрипт завершился без сообщений боту | Процесс не работает либо недоступна сеть | Проверь терминал, связь с Telegram и настройки прокси |
| Вместо ответа возникает исключение обработки | Ошибка в обработчике или подписи кнопки | Проверь стек вызовов, маршруты, тексты `lexicon_ru` |

## Исправленное несоответствие исходного кода

При подготовке документации в `handlers/other_handlers.py` обнаружилась сигнатура `async def send_answer(message, Message)`, где `Message` - второй обязательный аргумент, а не аннотация типа первого. Этот участок исправлен. Теперь обработчик имеет форму:

```python
@router.message()
async def send_answer(message: Message):
    await message.answer(text=lexicon_ru['other_answer'])
```

Это **выявленная и исправленная проблема кода**, а не подтверждённый результат тестирования в реальном Telegram. Всё ещё нужна ручная проверка неизвестного сообщения.

## Если меняешь инструкции

В описании неисправности должны быть: ожидаемый результат, фактический результат, команда/действие для повторения, среда, версия Python и релевантная часть traceback **без секретов**.
